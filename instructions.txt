------------

The docker-compose.yaml is ready. Here's what it sets up:

Infrastructure:

PostgreSQL 16 — main database on port 5432, with healthcheck
Neo4j 5 — knowledge graph DB on ports 7474/7687, with APOC plugin
Redis 7 — message broker on port 6379
Application:

api — FastAPI backend on port 8001 (runs Alembic migrations on startup, then Gunicorn)
celery-worker — background task processor for repo parsing and agent tasks
ui — Next.js frontend on port 3000
flower — Celery monitoring dashboard on port 5555 (opt-in via --profile monitoring)
Key design decisions:

All service connection strings are overridden in environment: to use Docker-internal hostnames (postgres, neo4j, redis) — your .env file only needs API keys and feature flags
api and celery-worker share a project_repos volume so cloned repos are accessible to both
Services wait on healthchecks before starting (depends_on with condition: service_healthy)
Flower is behind the monitoring profile — only starts with docker compose --profile monitoring up
To use:

Copy .env.template to .env and fill in at minimum OPENAI_API_KEY (or your preferred LLM provider key)
Run:

docker compose up --build
Access the app at http://localhost:3000, API at http://localhost:8001/health
Optionally add Flower: docker compose --profile monitoring up --build

All volumes now bind-mount under ./data/:

Host path	Container path	Service
./data/postgres/	/var/lib/postgresql/data	PostgreSQL
./data/neo4j/data/	/data	Neo4j
./data/neo4j/logs/	/logs	Neo4j
./data/redis/	/data	Redis
./data/projects/	/app/projects	API + Celery
To reuse this data from another project, just point at the same absolute path (e.g. d:/code/github-forks/potpie/data/postgres). Also added data/ to .gitignore to keep it out of version control.
